CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Commands

# Preview site locally
quarto preview

# Build site (output goes to docs/)
quarto render

# Convert publications.xlsx to publications.yml (runs automatically on render)
python xlsx_to_yml.py

# Install Python dependency for xlsx conversion (one-time)
pip install openpyxl

The built site lives in docs/ — GitHub Pages is configured to serve from that directory.

Architecture

This is a Quarto academic website. The source .qmd files render to static HTML in docs/. Navigation and global settings are controlled entirely by _quarto.yml.

Key files

  • _quarto.yml — site-wide config: navbar, footer, theme, analytics. Comment/uncomment entries here to show/hide pages.
  • index.qmd — homepage
  • people.qmd — team page; pulls data from YAML files in people/
  • pub-listing.qmd — auto-generated publications page; reads publications.yml via the pub-listing.ejs template and pub-listing.css
  • publications.qmd — manually curated publications page
  • projects.qmd — grants/projects page (currently commented out of the navbar)
  • posts.qmd — listing page for all posts (filtered by #category=news, #category=paper, etc.)
  • remove-stray-divfence.lua — Lua filter that strips stray ::: artifacts produced by the EJS listing template

Content data model

Content type Source
Team members people/*.yml (one file per role: pi.yml, researcher.yml, phd-student.yml, etc.)
Publications publications.xlsx → auto-converted to publications.yml via xlsx_to_yml.py
Grants/projects projects.yml
Posts (news, papers, events, presentations) posts/<post-folder>/index.qmd with YAML frontmatter categories: [news|paper|event|presentation]

People YAML format

Each person entry follows this pattern (indented under a list, no top-level key):

   - path: https://personal-website-or-linkedin.com
     image: "/files/profiles/photo.jpg"
     title: "Full Name"
     subtitle: "Role"
     categories: [Role Category]
     started: "2023"
     ended: "ongoing"   # use "ongoing" for current members

Profile images go in files/profiles/. The people.qmd listing controls which role files are included and whether alumni appear.

Publications workflow

  1. Edit publications.xlsx (columns: Section, Authors, Year, Date, Title, Paper Link, Journal, Volume, Issue, Pages, DOI + optional PDF, GitHub, Code, Data, Categories, etc.)
  2. python xlsx_to_yml.py converts it to publications.yml (runs automatically before quarto render)
  3. Use Section: Selected Work or Section: Peer-reviewed Journal Paper to place entries in the correct section of pub-listing.qmd

Showing/hiding pages

To temporarily remove a page from the navbar, comment out its entry in _quarto.yml under website.navbar.left. Example pattern already used in the file:

# - text: Grants
#   href: projects.qmd

Posts

New posts go in posts/<post-slug>/index.qmd. Set categories in frontmatter to route the post to the correct navbar filter (news, paper, event, presentation). The draft: true frontmatter key hides a post; draft-mode: unlinked (set in posts/_metadata.yml) means drafts are built but not linked from listings.
